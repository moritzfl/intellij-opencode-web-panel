## Source Layout

- Main sources: `src/main/kotlin/de/moritzf/opencodewebpanel`; tests mirror them under `src/test/kotlin/...`.
- Packages, by dependency direction (each may depend on the earlier ones, never the later):
  - `server` — process lifecycle, protocol/REST helpers, and the JVM `/global/event` reader: `OpenCodeServerBackend` / `OpenCodeServerBackendRegistry`, `SharedOpenCodeServerManager` (native), `SbxCli` / `SbxOpenCodeServerBackend` (Docker Sandboxes), `OpenCodeServerProtocol`, `OpenCodeGlobalEventStream`, plus lifecycle/log/terminator/MCP-startup support.
  - `browser` — page-injection mechanics: `OpenCodeBrowserSnippets` (all injected-JS builders), `OpenCodeBrowserScriptScheduler`.
  - `features` — the enhancements: agent-status, notifications, interrupted-session recovery, VCS refresh, IDE navigation, diff navigation, chat input, file drop, localStorage mirror.
  - `toolWindow` — JCEF/tool-window glue: factory, content, title/gear actions, status panels, request/shortcut handlers.
  - `settings` — settings state, secure password storage, settings UI (used by all of the above; restart confirm/dispatch reaches back into `toolWindow`).
- Metadata: `src/main/resources/META-INF/plugin.xml`. Icons: `src/main/resources/icons`. README screenshot: `docs/opencode-web-panel.png`.

## Conventions

- Runtime Host vs Docker Sandbox (`sbx`) is **per project** (`opencode-sbx.yaml` `useSandbox`). Host CLI and SBX are both one process per canonical project directory (`SharedOpenCodeServerManager` / `SbxOpenCodeServerBackend`). Resolve via `OpenCodeServerBackendRegistry.backendFor(project)`.
- In-VM serve binds `0.0.0.0:4096`; host URL is published `127.0.0.1` from `sbx ports --json` **after** health. Never parse `listening on http://0.0.0.0:4096` as the browser URL. Probe every loopback mapping; a stale first mapping can reset while serve is already listening. If none answer, publish again (do not abort start when `sbx ports` fails).
- Foreground `sbx exec` is the owned process; never `sbx run` TUI; never `sbx run -- serve`; never `exec -d` for serve; mixin `--kit` allowed, never `extends: opencode`; never set `HTTP_PROXY` inside the VM; never silent `policy init`.
- SBX launch spec lives in `opencode-sbx/` (`opencode-sbx.yaml`, `opencode-sbx.sh`, optional `opencode-network-kit/`). Colleague without the plugin: `./opencode-sbx/opencode-sbx.sh` / `--web` starts serve, `--cli` starts the TUI via `sbx exec -it`, `--acp` starts `opencode acp` via `sbx exec -i` (stdio JSON-RPC, no TTY), never `sbx run`. Windows: run the `.sh` from Git Bash; the plugin does not write a `.cmd` wrapper. Plugin Apply/start writes them. Machine copy under `~/.config/opencode-web-panel/sbx/`. No passwords in yaml. Install/network/env go through mixin kits (`--kit`). Project settings can write `opencode-sbx/opencode-network-kit/spec.yaml` (common hosts commented out). Ignore legacy `setupCommands` / `networkAllows`. Load still accepts project-root `opencode-sbx.yaml` / `opencode-web-panel.sbx.yaml`. Project YAML is the source of truth for every field it stores (including `hostPort`); hydrate UI and serve from it. Changing the OpenCode directory always loads the destination spec when it exists — do not prompt to keep the previous form. XML port is a fallback only when the spec is missing. Do not persist `.idea/opencode-web-panel-project.xml` when project directory and port are still defaults — `portImportedFromApplication` is in-memory one-shot and must not create that file.
- Project YAML owns all sandbox options. Startup may seed a missing spec from app defaults, but must not rewrite an existing spec from those defaults. Apply writes `canonicalDirectory: ./`; load resolves that against the **project** (parent of `opencode-sbx/` when the spec is nested) and derives the local sandbox name. Machine copies keep an absolute directory. Preserve Git kit `#ref` fragments and quoted path hashes. Run provisioning with the project cwd so relative kits work when the IDE starts in `/`.
- Appending uniquely named kits uses `sbx kit add` on the serial worker and preserves the owned sandbox identity/session volumes. Checkpoint each successful addition; never retry it after a later addition fails. Removing/reordering kits still changes create-time provisioning. Editing an installed local kit does not auto-apply: `sbx kit add` of the same reference rejects duplicate names (verified on sbx 0.39.0), so do not implement a fake hot-refresh. All outbound TCP requires hostname `"*"` plus IPv4/IPv6 CIDRs; CIDRs alone do not allow requests classified as `net:domain`. Balanced does not include xAI. Template comments must make these limits explicit.
- Sandbox **Upgrade OpenCode**: stop serve (keep VM), stream `sbx exec …` of guest `opencode upgrade --print-logs` (2.x adds `--method curl`) into the server log + strip stage + progress indicator, then start serve. CLI 2.x curl-detect compares `process.execPath` to `$HOME/.opencode/bin/opencode`; the persist extra-mount makes that a symlink whose realpath is the host `sbx-opencode` dir, so detection fails without `--method`. 1.x stays kit `opencode upgrade --print-logs`. Do not buffer upgrade stdout until exit. curl `-#` bars (2.x install fallback when stderr is not a TTY; early ticks are `## 2.8%`, not only long `####` runs) set `ProgressIndicator.fraction` and must not become strip/indicator text — no-letter lines are bar-only (`parseCliProgress`); stage becomes `Downloading OpenCode…` (`nextCliProgressStage`). `RESTARTING` keeps the tool-window strip (Cancel / View log / elapsed / last CLI line). JCEF Basic auth keeps the last origin/password after stop so a parked page does not 401 into Chromium's login dialog; live `getServerUrl()` is still nulled. A challenge host of `localhost`, `::1`, or `127.0.0.1` matches any of those for the same port; any other host must match the server host exactly.
- Sandbox **OpenCode version** (`openCodeVersion: 1.x` \| `2.x` in project YAML, default `1.x`): 2.x extra-mounts a plugin-owned host dir (`~/.local/share/opencode-web-panel/sbx-opencode/<name>`, not host `~/.opencode`) onto `/home/agent/.opencode` (create-time, like persist sessions; independent of `persistSandboxSessions`). Probe `$HOME/.opencode/bin/opencode` after the VM is up and before serve; stream `curl https://opencode.ai/v2/install` → `bash --no-modify-path` if missing (retry, then `--version` from this-arch npm latest — opencode.ai “latest” can 404 on `linux-arm64` before the tarball exists), then launch that binary (`sh -c` dispatch). Stop/start keeps the binary. **Reset Sandbox** deletes the host copy. 1.x launches kit `opencode` even if a leftover 2.x binary is present — do not persist the 1.x kit. Apply changing the version is **RESTART**, not recreate. Load still accepts legacy `installOpenCodeV2: true`. `opencode-sbx.sh` honors the same field (`--recreate` drops the 2.x host copy). Needs guest network to `opencode.ai` and `registry.npmjs.org` for a first 2.x install. Never `extends: opencode`. Select **2.x before first start** when sharing a host OpenCode 2 config (1.x kit cannot parse v2 `mcp.servers`).
- SBX start/stop/restart/reset/upgrade operations share a per-backend serial worker. Queue cleanup before publishing Stop; a subsequent Start must not overtake it. `stopServer(onStopped)` completes after cleanup so runtime switches can reuse fixed ports. Apply captures the old backend before saving `useSandbox`. Preview `LIVE` (port remap, kit append) keeps the VM up and runs `sbx ports` / `sbx kit add` on the serial worker; only `RESTART`/`RECREATE` (and runtime/directory switches) stop. Memory/CPU/protect/persist labeled “applies at Reset” must not stop. A runtime/directory switch keeps the old VM and sessions; only explicit Reset or create-time provisioning changes remove it. CLI commands never block the EDT; drain command output concurrently with bounded timeouts. Surface command-stage/exit diagnostics and fail early when serve exits, without booting a stopped VM for cleanup.
- Password: PasswordSafe → ProcessBuilder env → bare `-e OPENCODE_SERVER_PASSWORD`. Persist sandbox id; ownership `matches` is id-only (extra workspaces from protect/persist must not use `workspaces[0]`). Do not adopt by name/workspace alone.
- Share-host-config mounts the host OpenCode config directory as-is **read-only** (`sbx create … <config>:ro`; respect `XDG_CONFIG_HOME`), then passes its parent as `XDG_CONFIG_HOME` to serve. Never symlink over `/home/agent/.config/opencode`, which belongs to the built-in sandbox agent kit. OpenCode loads shared JSON/JSONC and relative file/plugin paths natively; the sandbox cannot write them. Embedded file credentials are readable too, but host `auth.json` and the host credential database are never read, copied, or modified by the plugin or launcher. No IDE-owned OAuth proxy. Provider access must work without IntelliJ: native `sbx secret` API-key injection or a separate OpenCode login inside the sandbox (`/connect`, `auth login`). OpenCode owns token refresh and credential storage. Do not strip sandbox-owned OAuth or seed host credentials into persist. Do not point guest `HTTP_PROXY` at the IDE/corporate proxy. Sessions and web localStorage remain separate. Existing share-config VMs created read/write keep that bind until Reset Sandbox.
- `protectSandboxFiles` (default on) overlays the `opencode-sbx/` directory (spec, launchers, extra-network kit) and other local kit **directories** as extra `:ro` workspaces so the RW project tree cannot change them; spec/launcher files cannot be extra workspaces (`sbx` requires directories). Git/OCI kits are not host mounts. Overlay paths are create-time only and are not compared against `sbx ls` workspaces. Start warns when the existing VM's create snapshot differs (protect overlays, memory/CPU, mounts) and offers Reset Sandbox. `persistSandboxSessions` (default on) extra-mounts a plugin-owned host dir (`~/.local/share/opencode-web-panel/sbx/<name>` on Unix, `%LOCALAPPDATA%\\opencode-web-panel\\sbx\\<name>` on Windows — not host `~/.local/share/opencode`) and symlinks `/home/agent/.local/share/opencode` to the in-guest bind (`guestBindPath`: Windows `C:/Users/...` → `/c/Users/...`). This preserves sandbox logins as well as sessions. Do not set `XDG_DATA_HOME` to the host path (in-VM mkdir of `/Users/…/.local` is EACCES). Never share Host CLI `opencode.db`. Persist mounts are create-time only (not `sbx ls` identity). Never `rm -rf` guest OpenCode data unless that persist host path is already a workspace; copy existing guest data onto the host path before replacing the directory with a symlink. Adopted VMs keep unknown provisioning and are not auto-removed. Invalid project YAML fails closed (sandbox error), never Host CLI.
- `backendId` on lifecycle/`connected()`. Native publishes `native:<sandboxName(dir)>` (`OpenCodeServerBackend.isNative`). Unbound fallback hashes the token `unbound`.
- Live JSON fixtures live next to `SbxCli` tests; refresh on `sbx` upgrades.
- Sandbox MCP overlays preserve the shared document's schema: flat `mcp.<name>` stays flat with `enabled`, scalar timeout and camelCase OAuth; native `mcp.servers.<name>` stays nested with `disabled`, object timeout and snake_case OAuth. OpenCode 2 migrates legacy documents itself. Wrapping a legacy entry in `mcp.servers` silently drops the document (verified on 2.0.12). An IDEA-only overlay uses the selected `openCodeVersion` schema. Shared native V2 config still requires a V2 guest. Generate an overlay only for IntelliJ MCP or shared loopback MCP URL rewrites and pass it through bare `-e OPENCODE_CONFIG_CONTENT`. No redundant `OPENCODE_CONFIG` file; never put token-bearing MCP config in the project or shell source. Never inject provider/model/transport compatibility overrides; OpenCode and user configuration own those. Shared `XDG_CONFIG_HOME` uses `guestBindPath` on Windows.
- `sbx ls --json` retains `:ro` on read-only workspace entries. Strip it with `workspaceHostPath` when checking extra mount presence, or every Start with shared host config falsely detects a missing mount and recreates the VM.
- Guest 2.x validation executes `$HOME/.opencode/bin/opencode --version` with GNU `timeout` (10s + 2s kill grace). Only exit 44 means absent and triggers installation; non-executable, wrong-major, unknown-version, failed, or hung binaries fail with diagnostics. Recheck after install/upgrade. V2 dispatch must never fall back to kit 1.x if the validated binary disappears.
- Guest 2.x installer and version probe live once in `opencode-sbx.sh`, in quoted `OCWP_V2_INSTALL` / `OCWP_V2_VERSION` heredocs. `SbxCli` extracts those same blocks from the classpath launcher for IDE commands; never duplicate their bodies in Kotlin. Keep heredocs in standalone functions, outside `$(...)` (macOS Bash 3.2 misparses case patterns in nested heredocs). `SbxLaunchSpec.installLaunchers` writes one `.sh` and removes the obsolete `opencode-sbx-install-v2.sh` / `opencode-sbx-version-v2.sh` helpers and `opencode-sbx-config-v2.json` provider overlay.
- Standalone ACP saves the caller's stdin/stdout before setup, runs provisioning with `/dev/null` stdin and stderr-only output, then restores both only for the final `sbx exec -i`. Even non-interactive `sbx` setup commands consume queued stdin; otherwise the editor's first `initialize` disappears. Verify with an immediate JSON-RPC request, not a delayed write after startup.
- Existing 1.x VM → 2.x is a restart, not a recreate. Its new binary stays VM-local until Reset applies the host binary mount. Verified on sbx 0.39.0: unchanged VM id and no reinstall after Stop/Start. Standalone health checks reject SPA HTML and accept JSON health or CLI identity (`/api/info`, older `/api/status`).
- Browser/tool-window state is project-scoped. The JCEF profile itself stays application-shared for Host CLI panels. Mirrored localStorage is application-wide and settings-only (`settings.v3`, theme, language, model favorites). Do not persist tabs, layout, `home.servers`, workspace, or notification lists — isolated serve processes per project do not share those.
- Browser shortcuts use component-local IntelliJ actions: reserve remappable IDs with `EmptyAction` in `plugin.xml`, register runtime handlers on the JCEF component with the reserved action's live `shortcutSet`, and inherit generic edit chords from `IdeActions`. Never use an application-wide key dispatcher or manually match incoming AWT key events.
- OpenCode-specific actions forward through a page-local `KeyboardEvent`, resolving OpenCode's current `settings.v3` keybind first. New Session maps to `tab.new` (v2) / `session.new` (classic); Close Tab maps to `tab.close`; Home maps to `home.toggle` / `sidebar.toggle`, selected by `[data-slot="titlebar-v2"]`. Do not construct AWT events for `CefBrowser.sendKeyEvent` — their missing Windows native scan codes break command delivery.
- Call sites use `OpenCodeServerProtocol` for command construction, auth/URL helpers, path detection, and route encoding. Command construction lives in `OpenCodeProcessLaunch`; turn and suspend classification lives in `OpenCodeRecoveryClassifier`. Injected-JS builders belong in `OpenCodeBrowserSnippets`.
- JCEF/tool-window integration stays in `toolWindow` (`OpenCodeWebToolWindowFactoryImpl`, `OpenCodeWebToolWindowContent`). Title-bar and gear actions live in `OpenCodeToolWindowActions`; title actions stay few and icon-only (IntelliJ clips them on narrow panels) and the gear menu must duplicate every title action.
- `OpenCodePanelController` owns one live browser and a stable Swing container per project. `OpenCodeEditorFile` borrows that container through IntelliJ's `UIComponentVirtualFile` / built-in editor provider, with `FORBID_TAB_SPLIT` so native tab moves cannot duplicate the panel. Closing the editor returns the container to the tool window; it never disposes the browser. Explicit Move actions change placement; chat actions and notifications activate the current host. Shared title/gear actions serve both hosts. Replacement swaps only the browser inside the stable container after the successor is ready, including if placement changed while waiting. The controller owns the single chat dispatcher, so constructing a successor and disposing its predecessor cannot steal or unregister delivery.
- Restart OpenCode Server is the recovery hammer: restart the shared process and replace tool-window content (new JCEF). Renderer crashes replace the panel without restarting the server. Stop→Start still keeps the existing document — never `about:blank`. Never stop the JVM `/global/event` reader (`HttpURLConnection.disconnect`) on the EDT — `ChunkedInputStream.close` waits on the lock the reader holds, which froze Restart. Disconnect in the background. A new JCEF must not wait the full document-start timeout before navigating; about:blank bootstrap can hang, and the onLoadStart fallback still injects.
- Panel replacement builds the new content **before** removing the old one, and never lets a JCEF failure escape. Out-of-process JCEF (Windows) answers a browser/message-router creation with no remote object while a sibling browser is being torn down (`RemoteMessageRouterImpl`: `Cannot read field "isNull" because "robj" is null`); the old order (dispose → create) both provoked that race and, when it threw, left the tool window empty forever — `createToolWindowContent` runs once. A failed replacement keeps the current panel; with no panel at all, `OpenCodePanelFailureCard` offers Retry. Page callbacks go through `OpenCodeJsQuery`, which turns a failed `JBCefJSQuery.create` into `inject() == null` (script builders then inject nothing) and makes the panel recreate itself once, throttled by `OpenCodePanelRecoveryPolicy`.
- A *running* page can also die silently: macOS out-of-process JCEF leaves the remote browser attached but stops delivering JS callbacks, with no load error or exception (JBR-10090) — the panel freezes until an IDE restart. `OpenCodeRendererWatchdog` covers that case: a page-side heartbeat (`buildRendererHeartbeatScript`, a post-load `InjectedFeature` gated by `recoverStalledRenderer` and the `rendererHeartbeatQuery` channel) posts into a JBCefJSQuery every 5s **and** on `visibilitychange` (never from `requestAnimationFrame` — that floods OOP JCEF IPC). On staleness the watchdog (`OpenCodeRendererWatchdogPolicy`) reloads the page in place and escalates persistent stalls to `replaceOpenCodeToolWindowContent`. Recreates are counted **process-wide** (a watchdog-built new panel does not reset the budget; a heartbeat from a panel born at the current recreate generation does — a sibling that was already alive does not; user Restart and the failure-card Retry zero it; without those the budget decays, halved per `RECREATE_BUDGET_HALVING_MILLIS` of silence) and capped by `MAX_STALLED_RECREATES` so a broken JCEF stack ends on the failure card instead of looping. Hidden pages freeze the stall clock rather than skipping the check. Re-showing the host forgets a stale page-hidden flag (a renderer that died while hidden cannot post `visible`). A not-yet-loaded page freezes only for `NOT_READY_GRACE_MILLIS` (each page-load attempt's document-start wait plus load timeout, times the retry budget); after that a hung “Opening the OpenCode page…” strip is a stall so Restart's new JCEF can still recover. While an agent turn is busy the timeout stretches to `BUSY_STALL_TIMEOUT_MILLIS` (long IPC bursts); the busy state comes from `OpenCodeAgentStatusTracker.hasBusySessions` (a pending permission must not mask it) and tracks even when the badge setting is off so the busy timeout keeps applying. Re-enabling the badge applies `currentState()` immediately. Nothing pings back into the page — staleness is the signal. `onLoadStart` only moves the stall clock (`noteDocumentLoadStarted`); it must not zero the recreate budget. `onAddressChange` only dismisses the Opening strip — it must not mark the page ready for the renderer watchdog. A load-retry exhaust marks the page ready for the renderer watchdog (`pageLoadGaveUp`) so a failed first paint can still be recreated. Watchdog recreates pass through `markBrowserRecoveryAttempt` so they share the throttle with renderer-crash recovery instead of interleaving into a recreate storm. Recreate/give-up hop through `invokeLater` so the Alarm callback is not disposing its own panel. A missing page-to-JVM channel (`OpenCodeJsQuery` unavailable) degrades to "no acknowledgement": chat text and file drops still dispatch with a null result callback, and chat `inFlight` is completed as accepted so the queue cannot wedge. Restart's panel-replacement latch must clear after the attempt so a failed JCEF create cannot disable later Restarts.
- Settings state, secure password storage, and settings UI stay in `settings`. Store secrets only in IntelliJ `PasswordSafe` — never in XML or project files.

## OpenCode Server

- **Minimum supported OpenCode version: 1.18.0** (`OpenCodeServerProtocol.MINIMUM_SUPPORTED_OPENCODE_VERSION`). Below that, warn once; do not invent compatibility shims for pre-1.18 routes. **1.18 and CLI 2.x are both supported** (`OpenCodeWireProtocol`). Do not bump the floor to 2.x.
- Dual-stack detect is **JSON only** (HTML 200 is not a protocol). Order: `GET /global/health` `{healthy:true}` → `V1_18`; else `GET /api/info` numeric `pid` + string `version` → `V2_CLI` (CLI 2.0.8+); else `GET /api/status` same shape → `V2_CLI` (CLI 2.0.5); else `GET /api/health` `{healthy:true}` → `V1_18`; else `/api/health` numeric `pid` without `healthy` → `V1_18_EMBEDDED_V2` (1.18 SPA permission v2, **not** CLI 2.x); else `UNKNOWN`. CLI 2.x `/global/health` and `/doc` are SPA HTML; `/api/health` is 404.
- Launch: `opencode serve --hostname 127.0.0.1 --port <port> --print-logs`. Default host `127.0.0.1`; basic-auth username is always `opencode`. Native start parses the listen banner via `parseServerUrl`: CLI 2.x prints `server listening on http://127.0.0.1:<port>`; 1.18 (`packages/opencode`) prints `opencode server listening on …`. Accept both; still reject `0.0.0.0` (sandbox in-VM bind is not the browser URL).
- Child `HTTP_PROXY`/`HTTPS_PROXY` follow the Server-tab **HTTP Proxy** setting (`OpenCodeProxyMode`): IDE proxy (manual, or auto-detect/PAC resolved via `JdkProxyProvider` for `https://example.com`), inherited env, or stripped. Destination-specific PAC rules cannot be expressed as one env var. Loopback is always added to `NO_PROXY` when a proxy is set.
- Port is **per project** in `opencode-sbx.yaml` `hostPort` (omit = Auto). Settings UI and Host CLI/`sbx` publish hydrate from that file. `OpenCodeProjectSettingsState` keeps a fallback only when the spec is missing. Default `Auto select`; Fixed rejects non-numeric/out-of-range input on Apply (blank falls back to default). Host CLI: `--port 0` or `--port N`. Docker Sandbox: in-VM stay `0.0.0.0:4096`; Auto publishes `4096/tcp4` (ephemeral host port), Fixed publishes `127.0.0.1:N:4096/tcp4`. Port changes remap with `sbx ports --unpublish/--publish` on the running VM — do not recreate. Legacy app `portMode`/`fixedPort` are copied once into a project that still has the defaults, then written into yaml on Apply.
- When settings that affect the process change, stop the server and let the next tool-window load restart it.
- Compact layout: OpenCode switches compact(mobile)/wide(desktop) on a `(min-width: 768px)` `matchMedia` query. To force compact, patch `window.matchMedia` for that query and `(max-width: 767px)` **before** the SPA bundle loads (`onLoadStart`) so `createMediaQuery` initializes with compact matches and never subscribes to real resize events. No CSS class overrides for the layout switch. `forceCompactLayout` defaults **on**, so the panel normally renders the mobile layout (classic `session-review-*`/`data-file` review panel); the redesigned v2 review panel (`session-review-v2-*`) appears only with it off (desktop). CLI 2.x Home needs an accompanying `buildCompactHomeLayoutScript`: compact mode removes its project sidebar, but native CSS still reserves a 280px desktop column and caps the grid at 1080px. Target only `div:has(> section [data-component="home-session-search"]):not(:has(> aside))` to remove that cap and use one flexible column. The no-aside guard preserves V1 Home, which still renders its project sidebar even with the media-query patch (verified on 1.18.31). Gate this stylesheet with the same setting, keep it alive across head replacement, and remove it via the existing compact-toggle reload. Do not match Tailwind class names or alter session/review layouts.

## Settings UI

- Path `Settings > Tools > OpenCode Web Panel`; server group label `OpenCode Server`; app order: binary, sbx path, password, HTTP proxy.
- Two pages sit under Tools: the application one (`OpenCode Web Panel`) and the project-scoped one (`OpenCode Web Panel (Project)`). The suffix keeps the tree from showing the same label twice; `plugin.xml`'s `displayName` supplies the label before the class loads, so it must match `PROJECT_SETTINGS_DISPLAY_NAME`.
- Application page: Host CLI binary, password, HTTP proxy, Wait-for-MCP, write-logs, `sbx` path, network-policy consent, optional same-major OpenCode update notice. Native binaries first; Docker Sandboxes group at the bottom. No Restart/status/log/port here — those would pick the wrong backend.
- Project page: OpenCode directory, **Server** (status / Restart / View log / port / diagnostics for `backendFor(this project)`), Host vs Docker Sandbox, mounts, kits. Restart is this project only for Host CLI and SBX. Apply shows a live/restart/recreate preview. Create-time fields that lag the VM are labeled pending until Reset.
- Application Docker Sandboxes group shows a setup checklist (detect sbx, policy init). The tool-window strip shows start/restart stage, elapsed time, Cancel, View log, and Cancelled; recovery reasons stay on the strip. Restarting (including sandbox upgrade) keeps the strip; stopped uses the idle card.
- Project **Check sandbox setup** runs on the backend's serial worker using saved YAML; verifies owned VM id + running status before guest curl probes (`opencode.ai/v2/install`, npm registry availability, `models.opencode.ai/api.json`). It never boots a stopped VM or changes network policy. Server health, outbound reachability, and provider authentication are separate results; guest checks have bounded connect/read/process timeouts. Neither `sqlite3` nor `jq` is needed for authentication setup.
- The application page is a tabbed pane sized to the **selected** tab (`OpenCodeSettingsTabbedPane`) — `JTabbedPane` otherwise reports the tallest tab and gives a short tab the long tab's scrollbar.
- Binary: `Auto detect` or `OpenCode path` (with a `Detect` action that fills an editable path).
- Password controls: edit, generate, show, copy.

## Injection Safeguards

- Register every `OpenCodeJsQuery` before native browser creation or component display, including the file-drop result channel. Waiting for `onAfterCreated` before registering routers leaves the first document's callbacks silent on out-of-process JCEF even though `isAvailable` is true. The page looks usable, but the heartbeat watchdog reloads it after the idle/busy timeout. Panel construction installs the channels; replacement still waits for the successor's `onAfterCreated` before disposing the predecessor. Verified with the installed IDEA and `OpenCodeJcefLiveRuntimeSwitchTest.firstDocumentDeliversRendererHeartbeatsWithoutReload` (ten channels, three browsers, no preliminary reload).

UI-behavior settings (`openFileLinksInIde`, `enableCodeNavigation`, `openDiffsInIde`, `enableChatFileDrop`, `forceCompactLayout`, `hideWebsiteButton`, `fasterPathHoverPreview`, `recoverFailedChunkLoads`, `recoverStalledRenderer`, …) gate **browser-side JS/CSS injection** into the embedded web app. They are **safeguards**, not cosmetics: if an injected behavior breaks the OpenCode UI or conflicts with an update, the user must be able to disable it and get back a clean, unmodified web app.

- Disabled ⇒ generate/inject/schedule nothing; the script builder returns `null`.
- Toggled **off** at runtime ⇒ reload the page so listeners/patches/stylesheets are fully removed — never inject a "disable" script.
- Toggled **on** at runtime ⇒ inject immediately and/or reload as needed.
- Scripts that must run before the SPA bundle (e.g. `forceCompactLayout`, event-stream watchdog) are registered with Chromium `Page.addScriptToEvaluateOnNewDocument` before navigation, and still injected from `onLoadStart` as a fallback. `executeJavaScript` from `onLoadStart` is queued and can lose the race with the SPA bundle.
- Never open event streams or other long-lived connections from injected scripts; consume OpenCode events JVM-side instead (see Event & REST Contract).
- Add unit tests asserting disabled builders return `null` and that a toggle-off reloads rather than injects a "disable" script.
- Validate injected JS against a real page before claiming it works (see Validating Against a Real Server) — unit tests only check the script *text*, never real DOM behavior.
- Prefer **locale- and design-independent DOM signals** over label text or Tailwind utility classes: `data-slot`/`data-component` attributes, `href` targets, and sprite-icon references (`use[href="#opencode-icon-<name>"]` — both toast generations render icon *names* into the DOM this way). The project-switch toast suppression matches the permission/question toast purely structurally: toast container + icon slot containing the `checklist`/`bubble-5` sprite icon + an action row; never translated strings.
- Early injection is centralized: `EarlyInjectedFeature` instances (seed → matchMedia → compact Home width → hide-website → path-hover preview → event-stream watchdog → chunk-load recovery, order matters) are combined into the document-start script and also run through `injectEarlyFeature` from `onLoadStart` with early-series retries; builders are re-invoked per attempt and must be idempotent in-page. Compact layout and IDE theme share one `matchMedia` wrapper. Post-load features use `InjectedFeature`/`scheduleFeatureScript`. Add new injections to one of these lists — do not hand-roll per-feature flags.
- A newly created empty JCEF browser has no renderer/DevTools page target even after `onAfterCreated`. `OpenCodeDocumentStartInjector` briefly loads `about:blank`, waits for a main document, registers the combined document-start script, and only then lets the caller navigate to OpenCode. Do not use a non-null `devToolsClient` as readiness proof, and do not reuse this transient bootstrap for the stopped-state card (the Windows Stop→Start path must keep the existing document alive). `CefBrowser.hasDocument()` can throw (`RemoteBrowser` unboxes a null RPC result) — wrap with `safeCefBoolean` (false = not ready) and never let a throw from `installAsync` skip the page load.
- Injected MutationObservers must be cheap in steady state: hiding is done by an installed stylesheet, and the observer only re-attaches the `<style>` (rAF-debounced) if the SPA replaces `<head>` — never per-mutation `querySelectorAll` work on the whole document.

### Path hover preview (`fasterPathHoverPreview`)

OpenCode's session-tab popover waits 2000ms (`titlebar-tab-popover` `OPEN_DELAY`). The panel clamps that Kobalte `window.setTimeout(..., 2000)` to 250ms — but only for two-argument 2000ms timers scheduled within a short window of a `pointerenter` on `[data-component="session-tab-popover-trigger"]` (Kobalte schedules the open-delay synchronously in its pointerenter handler); clamping every 2000ms timer while a trigger is hovered would also clamp unrelated page timers (copy-state reset, typewriter cursor). The skip-window `0` delay is left alone. Home rows (`[data-component="home-project-row"]` on 1.18, `home-session-row` on CLI 2.x) have no worktree in the DOM — 1.18 maps row order onto `opencode.global.dat:server` `projects` and skips when counts do not match; CLI 2.x uses `[data-component="home-session-project-name"]` only when that basename uniquely matches a stored worktree. It reuses `session-tab-popover` slots for page CSS. Toggle-off reloads.

### Page event-stream watchdog (`recoverStalledEventStream`)

OpenCode's page-side reader (`packages/app/src/context/server-sdk.tsx`) reconnects **only when its response iterator ends or throws**. It has no read timeout, and its only resume hook is `pageshow` with `event.persisted` — which never fires for a live JCEF page. A socket the OS severed without resetting it (sleep, VPN/adapter change; routinely half-open on Windows) therefore delivers neither bytes nor an error and `for await` blocks forever. Verified live against 1.18.10 behind a stalling proxy: the page issues **one** `/global/event` request and then ignores every server-side change until reloaded.

Two user-visible bugs share this single root cause, so treat them as one:

- the panel refuses new messages and looks frozen until a manual reload;
- a permission answered from an IDE notification stays on screen — the SPA removes a request **only** on the `permission.replied` event (`server-session.ts`), never by polling, while the plugin's JVM reply succeeds on its own connection.

`buildEventStreamWatchdogScript` wraps `window.fetch` (and `globalThis.fetch` when it still points at the original) before the SPA bundle captures it — document-start first, `onLoadStart` as fallback. Do not set the installed flag until `fetch`/`AbortController` are actually wrappable, or a too-early attempt permanently no-ops the retries. The OpenCode SDK calls `fetch(new Request(url))`; match `Request.url` and `URL.href` as well as string URLs, and rebuild a `Request` when overriding its signal. The wrapper pipes the event-stream body through a reader that aborts the request after 45s without a byte — three to four missed `server.heartbeat`s (10s cadence), the same budget as the JVM reader's read timeout. The abort surfaces as an ordinary stream error, which is the signal OpenCode's own reconnect loop already handles, so **recovery must stay out of SPA internals — never reload the page or reimplement the stream here.** `buildForceEventReconnectScript` cuts the stream on demand and is fired from the suspend-resume listener; it is a no-op when the watchdog is off.

Reconnect also repairs state missed while dead: the server emits `server.connected` on **every** new connection (verified), and the SPA re-bootstraps active directories on it, re-seeding pending permissions from `GET /permission` and clearing sessions that have none.

Match on `URL.pathname` for `/global/event`, `/event`, and `/api/event` so origin rewrites and `directory`/`workspace` query params cannot bypass the watchdog, and chain the caller's `AbortSignal` into the wrapper or the SPA's own `stop()` leaks the previous connection on every reconnect.

### Page chunk-load recovery (`recoverFailedChunkLoads`)

CEF only reports **main-frame** load failures to the JVM (`onLoadError`, the 20s page-load watchdog). A timed-out or 404 lazy `import()` of `/assets/<chunk>.js` (typical after a server restart left the SPA on a dead origin, or a first-run Windows hang) is a subresource: Chromium rejects the dynamic import, OpenCode's error boundary renders "Failed to fetch dynamically imported module", and the plugin never hears about it. Chromium also caches the failed import per renderer, so retrying the import keeps failing until a full reload.

`buildChunkLoadRecoveryScript` runs document-start / `onLoadStart` (a boot chunk can already be the failing one). It does **not** reload the page itself — it signals once via `JBCefJSQuery`, and the JVM calls `verifyServerNow` then `reloadOpenCodePageOrLoad` (one shot per document). Listeners: capture-phase `error` (module `<script src>`), `unhandledrejection` (uncaught `import()`). Solid's error boundary often **catches** the rejected `lazy()` promise (route chunks such as `new-session-*.js`), so those events never fire; the same engine TypeError is then copied into the error-page details field (not a localized label). A `setTimeout`-retried scan of **readOnly** `textarea`/`input`/`[data-slot="input-input"]` values covers that path (`requestAnimationFrame` does not run in a hidden JCEF tool window, and editable inputs can legitimately hold pasted engine text — reloading a healthy session is worse than missing the scan) and disconnects after the first signal. A stale origin the panel itself loaded still recovers (port remap); `reloadIgnoreCache` avoids serving the HTML that referenced the missing chunk. Do not match translated chrome ("Something went wrong").

### Diff navigation DOM contract (`openDiffsInIde`)

The Ctrl/Cmd+Click or Alt+Click "open diff in IDE" feature (`OpenCodeBrowserSnippets.buildDiffNavigationScript` → `features.OpenCodeDiffNavigation`) maps a click to `messageID` / `filePath` / `partID`. Chat edit/write/patch targets live in the shared `session-ui` `MessagePart` (layout-independent). Re-verify the selectors against a live page whenever diffs stop opening:

- **Message id** — nearest `[data-message-id]` ancestor (one per session turn; holds the turn's **user** message id). Used by `session.diff` for review/turn-summary/whole-turn. Never send an empty or assistant id (both yield an empty snapshot diff). (Pre-1.18 `[data-message]` no longer exists in the bundle; the fallback was removed.)
- **Part id** — nearest `[data-timeline-part-id]` on `[data-component="tool-part-wrapper"]` (`prt_…`). Chat edit/write/patch use this, not reconstructed title text. There is no GET-by-part (only DELETE); the JVM pages `GET /session/{id}/message?limit=50` via `X-Next-Cursor` / `before` until that id appears in `parts[]`.
- **Changes/review row** — `[data-file]` (path directly) → `session.diff`.
- **"Changed files" turn-summary row** — `[data-slot="session-turn-diff-trigger"]` (no `data-file`; reconstruct path from `[data-slot="session-turn-diff-directory"]` + `[data-slot="session-turn-diff-filename"]`) → `session.diff`. **1.18-only**; CLI 2.x has no `session-turn-diff-*` slots — fall back to `[data-message-id]` on `user-message`/`text-part`.
- **Chat edit/write/single-file patch** — `[data-component="edit-tool"|"write-tool"|"apply-patch-tool"]` → `partID` only. Edit: `state.metadata.filediff.{file,patch}`. Write: no patch on the part (`state.input.filePath` / `metadata.filepath`) then `session.diff` for that file. Apply-patch: `state.metadata.files[]`. CLI 2.x still sets `edit-tool`/`write-tool` but drops `edit-trigger`/`write-trigger`/`message-part-title-filename`; the file accordion header reuses `[data-slot="apply-patch-trigger-content"]` + `apply-patch-filename` / `apply-patch-directory`.
- **Multi-file patch row** — `[data-slot="apply-patch-trigger-content"]` → `partID` plus reconstructed `relativePath` from `[data-slot="apply-patch-directory"]` + `[data-slot="apply-patch-filename"]` to pick the `files[]` row (exact / unique-suffix match against `relativePath`, never the turn snapshot).
- **Diff indicator** (fallback → whole turn, all files) — `[data-component="diff-changes"]` outside a tool block → `session.diff`.

The file-link handler (`buildFileLinkHandlerScript`) early-returns on Alt and Ctrl/Cmd+Click, reserving those for this gesture. Diff-nav is injected first so it wins on overlapping targets.

Conversation diffs keep reconstructed snapshot text (`OpenCodeUnifiedDiff.sides`) but pass the workspace file as `DiffContentFactory.create(project, text, virtualFile)` `highlightFile`, so Jump to Source (F4) opens the original at the translated line. Do not `create(project, virtualFile)` — that shows current disk content, not the conversation snapshot. Skip highlight when the file is gone. Resolve with `guessIncomplete = false` (never F4 to a guessed sibling). Sandbox paths go through `OpenCodeHostPaths`.

### Review-panel file links (`openFileLinksInIde`)

Two review panels exist, selected by width: the plugin's default forced-compact mode shows the **classic** panel; with `forceCompactLayout` **off** (desktop) OpenCode shows the redesigned **v2** panel (`session-ui/src/v2/components/session-review-v2*`, a sidebar tree + preview pane). `buildFileLinkHandlerScript` must resolve "open in IDE" in both:

- **Classic** — the per-file "open" button (`[data-slot="session-review-view-button"]` only — no locale-specific aria/title fallbacks); path from a `[data-file]`/`[data-path]`/`session-review-accordion-item` ancestor, else the `session-review-file-info` spans (`session-review-directory` + `session-review-filename`).
- **v2** — no per-file button; resolve from the **preview header** (`[data-slot="session-review-v2-file-name"]` + optional `[data-slot="session-review-v2-file-path"]`, inside `[data-slot="session-review-v2-file-title"]`). Do **not** hijack the sidebar rows (`[data-slot="session-review-v2-sidebar-tree"] button[data-path]`) — those are the SPA's own preview navigation.

CLI 2.x Changes tab (`[data-slot="session-review-v2-sidebar"]` **with** `[data-component="select-v2"]`) is **not** always a conversation diff. Dropdown values (locale-independent `data-key`): `git` → `GET /api/vcs/diff?mode=working`, `branch` → `mode=branch`, `turn` (Last turn changes) → `session.diff` + file path. Default when the key is not yet copied onto the trigger is `git` (OpenCode's default). Files tab tree is the same `file-tree-v2-row` **without** that select — Alt/Ctrl/Cmd+Click opens the file (file-link), not a diff. Do **not** hijack plain clicks on the tree (SPA preview). Chat timeline Alt+Click is unchanged.

**Chat links arrive percent-encoded.** OpenCode renders markdown through marked, whose `cleanUrl` runs `encodeURI(href)` and then restores literal `%` via `.replace(/%25/g, "%")`; models also emit escaped paths themselves. A relative link to a path with a space or any non-ASCII character therefore reaches the JVM as `docs/My%20File.md` / `docs/%C3%9Cmlaut.md`, while plain ASCII paths pass through untouched — the reason only *some* relative links resolved. Rules the resolver must keep:

- `decodeFileLinkPaths` returns the decoded **and** the raw spelling (a name may legitimately contain `%`, and `cleanUrl` passes it through). `file:` URLs take `rawPath`/`rawSchemeSpecificPart` so the single decode is not applied twice.
- Each spelling carries the position that applies when *it* resolves, so `src/Main.kt:42` can be probed stripped (line reference) and whole (a file really named `…:42`) without the line leaking onto the wrong reading. Chat code-nav accepts the same locators plus `:L123-1234`, `#L42-L57`, `(42,13)`, and `(L98)`. A locator immediately after an inline `<code>` span is glued onto the span text (`Main.kt`:L42, `Foo.java` (L10)). `Type.method()` / `pkg.Type.method(…)` resolve to the type. Filename-index fallback only opens a **distinct** workspace match. Stack-trace tokens in `<pre>` / `[data-slot="bash-pre"]` / `[data-component="tool-output"]` use the same locators (any `.[A-Za-z][A-Za-z0-9]{0,8}` extension, not Java-only) plus Python `File "path", line N`; backticks may split path and locator there and are glued across; not PascalCase / bare filenames.
- `file:<relative>` is an **opaque** URI (`path` is null) — the exact form `localFileDropText` writes.
- Root-relative `/src/Main.kt` is absolute on Unix but *not* on Windows, where `resolve` would keep only the drive root. Decide on the href **text** (`startsWith('/')`), never `Path.isAbsolute`. A genuinely absolute path is tried literally first, so a project that also has `etc/`/`tmp/` yields the system file for `/etc/x`.
- Percent-decoding can produce text that is not a legal path (NUL anywhere, `<>?*|"` on Windows); every `Path.of` on link input must be guarded or the exception escapes the click handler.

**Incomplete references are guessed** (`bestGuessFileLinkPath`), only after every exact candidate across every base missed: first drop leading segments (`packages/app/src/x` under a base already inside `packages/app`), then a bounded walk for a file whose trailing segments match, ranked by matched segments → depth → path. The walk prunes `.`-directories plus build/VCS output and is capped (`SEARCH_MAX_DEPTH`, `SEARCH_MAX_VISITED_ENTRIES`). Because this can touch the filesystem broadly, `OpenCodeIdeNavigation.openFileLinkInIde` resolves on a pooled thread — never on the browser callback thread; a newer click invalidates any older in-flight result.

**SPA routes are not files.** The capture-phase file-link handler treats many `href`s that start with `/` as local paths. Keep `isOpenCodeAppRoute` (JS) and `isOpenCodeSessionRouteHref` (JVM) in sync and exclude at least:

- `/server/<key>/session[/<id>]` — 1.18 session routes (task/subagent cards, notifications, boot)
- `/new-session…`
- `/` and bare `/<base64url(dir)>` project roots when the segment decodes to an absolute filesystem path
- legacy `/<base64url(dir)>/session[/<id>]` when the segment decodes to an absolute path

Missing an exclusion → subagent cards and sidebar session links get `preventDefault` and never navigate.

Root-relative `/…` hrefs are files only when the last path segment looks like a file (`Main.kt`, `foo.md`). Unknown SPA paths like `/future-page` are left to the app. Windows drive/UNC paths are unchanged.

### Open-project navigation contract (OpenCode 1.18+)

OpenCode 1.18's SPA is **directoryless** for sessions. Canonical routes:

| Route | Role |
|---|---|
| `/server/<base64url(origin)>/session/<ses_…>` | Real session (SPA route requires `:id`) |
| `/server/<base64url(origin)>/session` | Id-less shell only — not a lasting SPA destination |
| `/new-session?draftId=…` | Draft composer |
| `/<base64url(dir)>/session[/<id>]` | Legacy; SPA may still emit it (sidebar/notifications) and redirects to the server form |

Which project a directoryless URL shows is **not** in the path — only in the SPA's `opencode.global.dat:server` localStorage (`lastProject` / `projects`), which lives in the **application-shared, persistent** JCEF profile. Cold-loading the legacy bare directory route **without** a session id crashes the SPA error boundary ("Unable to retrieve session" on every send). Consequences in `buildOpenProjectScript` / `OpenCodeWebToolWindowContent` / `OpenCodeServerProtocol`:

- **Boot URL** — tool-window load always uses `/` (Home), never a restored `ses_` (`loadProjectPageAt(…, sessionId = null)`). OpenCode 2 renders "This session cannot be found" for a boot URL whose id is missing on this serve (auto-port reuse, isolated per-project DB). Notifications still use `buildServerSessionUrl(serverUrl, sessionID)`. Never boot the id-less `/server/<key>/session` shell (empty `<main>`). Never use `buildProjectUrl` (legacy bare directory route). Session choice is OpenCode's (filtered tabs / `lastProjectSession`); do not REST-lookup "most recent" or overwrite the pointer. If the main document never reaches a successful `onLoadEnd` within 20s, retry up to twice (`OpenCodePageLoadWatchdog`) on its own Alarm. Do **not** `stopLoad` within that budget.

- Headful JCEF tests live under `src/test/kotlin/.../jcef/` and follow JetBrains `JBCefTestHelper` (ApplicationRule, show a JFrame, wait `onLoadEnd`, 60s CEF-init budget). They are opt-in: `rtk ./gradlew test -Pjcef`. `./gradlew check` stays headless.
- Editor lifecycle/split tests use `FileEditorManagerTestCase` (the ordinary light fixture uses a mock editor manager). The live `editorTransfersKeepRealComposerDraftAndCallbacksWithoutReload` test covers native editor round trips, browser callbacks, draft retention, and acknowledged chat delivery. Run against another CLI with `OPENCODE_JCEF_EXECUTABLE=/path/to/opencode rtk ./gradlew test --rerun -Pjcef '-PlocalIdePath=/Applications/IntelliJ IDEA.app' --tests '*OpenCodeJcefLiveRuntimeSwitchTest.editorTransfersKeepRealComposerDraftAndCallbacksWithoutReload'`. Its temporary project must be **opened**: a closed project uses teardown-only tab selection semantics and can return a disposed editor on reopen. Skip unrelated installed-IDE startup activities with `ProjectImpl.RUN_START_UP_ACTIVITIES`; use an IDE glass pane on the editor JFrame.
- Replacements must wait for the new browser's `onAfterCreated` before disposing the old panel, not just construct a Java wrapper. `createOpenCodeBrowserBeforeReplacement` bounds that acknowledgement wait; a failure keeps the old panel. Test with the installed IDE/JCEF using `-PlocalIdePath="/Applications/IntelliJ IDEA.app"` (the normal platform baseline can miss newer out-of-process JCEF failures).
- `OpenCodeJcefLiveRuntimeSwitchTest` starts two isolated real `opencode serve` processes (requires a local CLI), reproduces the empty id-less route, exercises repeated native/sandbox-equivalent browser replacement, and verifies a known session still has a composer. Run it with `rtk ./gradlew test -Pjcef --tests '*OpenCodeJcefLiveRuntimeSwitchTest'`; no provider calls or real sandbox mutations.
- **Open-project seed** — inject seed-only (`lastProject` + `projects` for this panel's directory into `opencode.global.dat:server`) from **`onLoadStart`** (before the SPA bundle reads localStorage). Post-load inject alone races the shared browser profile and can leave the panel on another IDE project's workspace. Worktree dedupe must treat Windows separators/drive case as equal. Seed the **OpenCode-canonical** directory (`canonicalOpenCodeDirectory` / realpath, then the spelling from `GET /api/session` `location.directory` when it is the same folder). The SPA's `session.get` is exact `session.directory === sdk().directory`; IntelliJ `basePath` (`/var` vs `/private/var`, symlink aliases) makes every send fail with "Unable to retrieve session". OpenCode 2 persists session tabs per origin (`opencode.window.browser.dat:tabs`); auto-port reuse across IDE projects reopens the previous occupant's `ses_` ids as "This session cannot be found". `buildOpenProjectScript` drops those tab keys when `opencode-intellij-project` is missing or not the same worktree, then writes that marker.
- **Last-viewed session pointer** — owned by OpenCode (`opencode.global.dat:layout.page` → `lastProjectSession`). Do not overwrite it from the plugin. `directory` in that value must be the **session's** stored path; `session.get` is exact `===`.
- **Open-project navigate** — seed-only. Cancel prior open-project delay series on `onLoadStart`.
- **Never** treat every `/server/…` URL as "already at the destination" JVM-side for project identity (`routeDirectoryFromUrl` returns null for directoryless routes; `isOpenCodeProjectDestination` only matches legacy directory-encoded paths). Project binding is the seed, not the path.
- **Notifications "Show in OpenCode"** — open via `buildServerSessionUrl(serverUrl, sessionID)`; `isOpenCodeRouteAlreadyOpen` treats the same `ses_…` under legacy vs server path shapes as already open (unless the target pins a different query).
- **Foreign-session warning** — opt-in (`warnForeignSession`, default off). On a displayed-session change (SPA route, including a restored tab), `GET /session/{id}` and compare `directory` / `location.directory` to this panel's OpenCode directory. IDE notification only; do not block navigation. Exact folder match only (a subdirectory is a different cwd). Symlink spellings (`isSameFilesystemPath`) and sandbox guest paths (`guestBindPath` / `guestToHostPrefixes`) are the same folder. A missing directory or a failed fetch is not a mismatch. Re-warn after the user leaves and selects that session again; do not re-warn when the address keeps the same `ses_`.
- A renamed project directory that keeps showing its **old path/name** is opencode's server-side stale `project.worktree` ([anomalyco/opencode#35240](https://github.com/anomalyco/opencode/issues/35240)) — not fixable from the plugin. Injection fixes and wire-contract checks must be validated against a live server — not `about:blank`, synthetic pages, or unit tests. A 2.x miss **fails** (do not `exit 0` on `_assets`). Run after changing selectors, SPA storage keys, media queries, icon names, command shortcuts, or injection targets. Add/change the marker or Persist classification in the same commit as the integration.
- **Wire gate** — `OPENCODE_SERVER_PASSWORD=testpw123 scripts/check-wire-contract.sh http://127.0.0.1:<port> <project-directory>` checks every consumed OpenAPI operation/operation ID for presence and deprecation, required event names, and live REST root/envelope shapes. Auto-detects CLI 2.x via `/api/info` (2.0.8+) or `/api/status` (2.0.5). Baselines: **1.18.31 = 15 operations + 5 live roots + 9 event types**; **CLI 2.0.5 / 2.0.8 = 10 operations**. - **Presence is not semantics** — passing gates cannot prove selector meaning, private storage shape, event payload semantics, or synthetic-event acceptance. Always run feature-specific Playwright against the real page after touching diff navigation, project seeding, file-link/code interception, toast suppression, compact/theme patches, or chat paste/drop. Unit tests only check generated script text and JVM state machines.

- Start: `OPENCODE_SERVER_PASSWORD=testpw123 opencode serve --hostname 127.0.0.1 --port <port> --print-logs`. Health: 1.18 `curl -u opencode:testpw123 http://127.0.0.1:<port>/api/health` ⇒ `{"healthy":true}`; CLI 2.x `/api/health` is 404, use `/api/info` (2.0.8+) or `/api/status` (2.0.5) `{version,pid,urls}` (curl with `-u` first to separate auth from app problems). CLI 2.x `/api/status` was renamed to `/api/info` in 2.0.8.
- **Basic auth covers everything** — the SPA's static assets (`/assets/*.js|css` on 1.18, `/_assets/*.js` on CLI 2.x) and all API routes; only `/site.webmanifest` and the web-app-manifest PNGs are public.

Instead send the `Authorization` header on **every** request (what the plugin does via `onBeforeResourceLoad`): `page.setExtraHTTPHeaders({ Authorization: 'Basic ' + btoa('opencode:testpw123') })` (or `httpCredentials`), set **before** the first `goto`. For `opencode:testpw123` the header is `Basic b3BlbmNvZGU6dGVzdHB3MTIz`.

- **Session route (1.18):** `/server/<base64url(origin)>/session/<ses_…>` — `serverKey` is base64url of the origin (no padding), same encoding as `encodeDirectory`. Example: origin `http://127.0.0.1:4096` → path `/server/<key>/session/ses_…`. Prefer this over the legacy `/<base64url(dir)>/session[/<id>]` form (still accepted by the SPA as a redirect).

## Event & REST Contract

The server publishes an **OpenAPI 3.1 spec** at `GET /doc` while running; the JS SDK (`@opencode-ai/sdk`) is generated from it but can lag, so cross-check against a live server or the source at `/Users/moritz/Desktop/git/opencode` (`packages/schema/src/`). The plugin consumes events **JVM-side**: `OpenCodeGlobalEventStream` (owned by `SharedOpenCodeServerManager` / `SbxOpenCodeServerBackend`) holds the single SSE reader (`/global/event` on 1.18, `/api/event` on CLI 2.x) and publishes parsed events on the `OpenCodeGlobalEventListener` application topic, emitting `connected()` after each (re)connect so consumers can re-seed reduced state via REST. Subscribe new consumers there; REST parsers live in `OpenCodeServerProtocol` with adjacent unit tests. Re-verify wire shapes against a real server after touching them or on OpenCode updates. Reduced-state consumers (e.g. `OpenCodeSoundService` busy tracking) must key their state by `event.backendId` — a restart/reconnect of one backend must not clear or satisfy another backend's sessions.

Reproduce: start a server (above), then in one terminal `curl -N -u opencode:testpw123 -H "Accept: text/event-stream" http://127.0.0.1:<port>/global/event`, and trigger events from another, e.g. `curl -u opencode:testpw123 -X POST "http://127.0.0.1:<port>/session?directory=<url-encoded dir>" -H 'Content-Type: application/json' -d '{}'`.

**Event framing (1.18):** SSE `data:` payloads are `{"directory": "...", "payload": {"id": "evt_...", "type": "...", "properties": {...}}}`. Events without a `directory` (e.g. `server.connected`) are dropped by `parseGlobalEvent`; `server.heartbeat` arrives every 10s.

**CLI 2.x:** `GET /api/event` payloads are `{id, created?, type, location?: {directory}, data}`. Heartbeat is SSE comment `: heartbeat` (~15s). `server.connected` has empty `data` — use the backend directory, do not drop. `session.execution.started|succeeded|failed|interrupted` map to `session.status` busy/idle. `permission.asked`/`.replied` names match 1.18; reply REST body is `{decision}` not `{reply}`. No question API (forms exist; IDE questions stay 1.18-only). OpenAPI is `GET /openapi.json`. Consumed types (v1, see `packages/schema/src/v1/`):

- `session.status` → `{sessionID, status: {type: "busy"|"retry"|"idle", ...}}`
- `session.idle` (deprecated predecessor of `session.status`) → `{sessionID}`
- `session.error` → `{sessionID?, error?}`
- `session.created` → `{sessionID, info: {id, parentID?, ...}}` (auto-accept caches parentID so nested subagent asks do not race `GET /session/{id}`)
- `permission.asked` → `{id, sessionID, permission, patterns, metadata, always, tool?}` (NOT `permission.updated` — that only exists in the stale legacy SDK gen)
- `permission.replied` → `{sessionID, requestID, reply}`, `reply ∈ {"once","always","reject"}` (NOT `{permissionID, response}` — stale gen)

**Permission v1/v2 are two disjoint stores — the panel is on v1.** The SPA's `detectServerProtocol` probes `/global/health` first and picks **v1** whenever it answers `{"healthy":true}` (it does on 1.18.10), so the embedded panel uses the v1 prompt path. There, `SessionTools.resolve` hands tools a `Tool.Context.ask` bound to the **v1** `Permission.Service`, which emits `permission.asked`/`permission.replied` and is answered by `POST /permission/{requestID}/reply`. The parallel v2 service (`POST /api/session/{sessionID}/permission`, `…/permission/{requestID}/reply`) emits **only** `permission.v2.asked` and its requests appear **only** in `GET /api/session/{id}/permission` — never in v1 `GET /permission` (verified live on 1.18.10 by creating one). Consequence: v1-only handling is correct today, but if a future server drops `/global/health` the SPA flips to v2 and the plugin would stop seeing permissions entirely rather than degrade. `detectWireProtocol` classifies 1.18 embedded-v2 separately from CLI 2.x (`V1_18_EMBEDDED_V2` vs `V2_CLI`) and warns once for embedded-v2. Re-check this before assuming a permission bug is a reply-endpoint problem.
- `question.asked` → `{id, sessionID, questions: QuestionInfo[], tool?}`
- `question.replied` → `{sessionID, requestID, answers: string[][]}`
- `question.rejected` → `{sessionID, requestID}`

Many other types exist but are unconsumed; durable events also re-emit as `sync` wrappers (`syncEvent.type = "<type>.<version>"`). See `packages/schema/src/session-event.ts`. There is NO `lsp.client.diagnostics` — only `lsp.updated`.

**REST shapes** (all take `?directory=`):

- `GET /session/status` → `{"ses_...": {"type": "busy"|"retry"|"idle"}, ...}` (`parseBusySessionIds`).
- `GET /permission`, `GET /question` → array of request objects with `id` (`parsePendingRequestIds`).
- `GET /session/{id}` → session object with `title` and optional `parentID`, bare or wrapped in `{"data": {...}}` (`parseSessionInfo`).
- `GET /session/{id}/children` → array of child session objects with `id` and `parentID`, bare or wrapped in `{"data": [...]}` (`parseSessionChildren`). Used by auto-accept to pre-cache nested subagent lineage when a parent is enabled.
- `GET /api/session?order=desc&limit=N` → `{"data": [{"id": "ses_...", "parentID"?, "time": {"created","updated"}, "location": {"directory"} | "directory"?}, ...], "cursor": {...}}` (`parseSessionList`). Creation-ordered (**not** by `time.updated`) and includes subagent children, so "most recent activity" callers must pick `max(time.updated)` themselves and skip entries with a `parentID`. Prefer `location.directory` (v2) then `directory` for `lastProjectSession.directory`. The server canonicalizes directories (macOS `/var/...` → `/private/var/...`); query with the same directory value used elsewhere.
- Interrupted-session recovery reads the **last message** via `fetchLastMessageJson` (v1 first, v2 fallback) and classifies it with `isInterruptedLastMessage` / `isSuspendSeveredLastMessage` / `isUnsettledTurnFromBefore`. Those classifiers expect a flat shape `{type:"user"|"assistant", time:{created,completed?}, error?, content:[{type:"tool", state:{status ∈ pending|running|completed|error}}…]}`.
  - **v1 (what the embedded SPA actually writes)** — `POST /session` + `POST /session/{id}/prompt_async`; messages at `GET /session/{sessionID}/message?directory=<dir>&limit=1` (op `session.messages`) → bare array of `{info:{role,time,error?}, parts:[…]}`. With `limit=1` the server returns the **newest** message. `normalizeLastMessageForClassification` maps `info.role` → `type` and `parts` → `content`.
  - **v2** — `GET /api/session/{sessionID}/message?order=desc&limit=N` → `{"data":[SessionMessage…],"cursor":{…}}`. Populated only for sessions created through the v2 API; for SPA sessions it returns `{"data":[]}`. Used as a fallback only.
  - Continue: `POST /api/session/{sessionID}/prompt` body `{"prompt":{"text":"Continue"},"resume":true}` works for both v1- and v2-created sessions (returns `delivery:"steer"`).
- `GET /session/{sessionID}/diff?directory=<dir>&messageID=<msg_...>` → `Array<SnapshotFileDiff>`, `SnapshotFileDiff = {file?, patch?, additions, deletions, status?: "added"|"deleted"|"modified"}` (`fetchSessionDiff`/`parseSessionDiff`). `patch` is a unified diff string; there is **no `before`/`after` field** (the legacy gen showing them is wrong). The same shape rides the `session.diff` event. **Keyed by the turn's *user* message id**: omitted or assistant `messageID` → `[]`; only the user `msg_...` returns that turn's diffs. Diffs come from persisted git snapshots (`<data>/snapshot/<projectID>/…`) and **survive a server restart**. Used for review-panel / turn-summary / whole-turn Alt+Click, and as the write-tool fallback. `OpenCodeDiffNavigation` reconstructs before/after from each `patch` via `OpenCodeUnifiedDiff` and binds both sides to the workspace file as highlightFile (F4 / Jump to Source).
- Chat edit/patch Alt+Click loads the tool part from `GET /session/{sessionID}/message?directory=<dir>&limit=50` (op `session.messages`; further pages via `X-Next-Cursor` + `before`). Bare array of `{info, parts}`. Tool parts live on the **assistant** message; the user `msg_` from `[data-message-id]` does not contain them. No GET `/part/{partID}` exists (that route is DELETE only). Shapes (`fetchToolPartChange` / `parseToolPartChange`):
  - edit: `state.metadata.filediff = {file, patch, additions, deletions}` (`file` is absolute)
  - apply_patch: `state.metadata.files[] = {filePath, relativePath, type, patch, additions, deletions, movePath?}`
  - write: no patch; `state.input.filePath` / `state.metadata.filepath` then `session.diff` for that file
  - **CLI 2.x edit** — no `filediff`. `state.metadata.files[] = {file, patch, status, additions, deletions}` (`file` is workspace-relative). Part ids are `call-<uuid>-N`, not `prt_`. Write still has no patch (`state.input.path`). Chat DOM: edit/write render as `[data-slot="apply-patch-trigger-content"]` after expanding `[data-component="collapsed-tool-group"]` (no `edit-tool` wrapper). Alt/Ctrl-click already hits that slot → `partID` + reconstructed path; turn fallback is `[data-message-id]` → `session.diff?from=`. Live 2.0.5: `GET /api/session/{id}/diff?from=msg_` returns `FileDiff.Info[]` for workspace files.
- `POST /permission/{requestID}/reply?directory=<dir>` body `{"reply": "once"|"always"|"reject"}` (op `permission.reply`) — the write endpoint for permissions (`replyToPermission`; `requestID` is the `per_...` id from `permission.asked`/`.replied`). Successor to deprecated `POST /session/{sessionID}/permissions/{permissionID}` + `{"response": ...}` (op `permission.respond`). Don't regress: a `{"response": ...}` body → `400 Missing key ["reply"]`; unknown id → `404 PermissionNotFoundError`.

If a shape changed, fix the matching parser and its unit test, then update this section.
